## 1. Prompt anti-patterns

### 1.1 Verification rituals — PASS
One benign hit (`playwright-tester/SKILL.md:183` "make sure the host app imports…"). skill-manager's mandatory validator is a single scoped tool run, not a duplicated reasoning loop.

### 1.2 Thoroughness & emphasis boosters — HIT (medium)
Your own meta-skill already legislates against this — `skill-manager/SKILL.md:94`: *"Explain why an instruction matters instead of stacking MUST/ALWAYS… Heavy caps-lock MUSTs are a yellow flag."* Three skills ignore it:

- `systematic-debugging/SKILL.md` — "The Iron Law", "ALWAYS find root cause" (L11), "You MUST complete each phase" (L61), "Use this ESPECIALLY when" (L26), "Violating the letter of this process is violating the spirit of debugging" (L13 — pure rhetoric, carries no semantics). 315 lines + 734 lines of references.
- `brainstorming/SKILL.md` — `<HARD-GATE>` custom tag, "You MUST create a task for each" (L23), "EVERY project regardless of perceived simplicity" (L19).
- `frontend-design/SKILL.md:72,93` — `**CRITICAL**` / `**IMPORTANT**` prefixing pure aesthetic advice. (L12/L14 "MANDATORY FIRST STEP" / "ALWAYS extending" are different — they encode a real precedence rule and earn their emphasis.)

**Fix:** rewrite the rhetoric as reasoned imperatives per skill-manager's own guide. The Iron Law → one sentence explaining why symptom patches fail under error-class recurrence (the skill already contains that argument). Delete "spirit of debugging" entirely.

### 1.3 Mandatory procedures & scaffolds — HIT (low)
Four-phase gating in systematic-debugging and the task-checklist in brainstorming are rigid procedure scaffolds. Mitigated: both are user-invoked (`disable-model-invocation: true` on brainstorming) or tightly trigger-scoped descriptions, so they don't tax ordinary turns. No "think step-by-step" scratchpad instructions anywhere. Leave unless trimming for tokens.

### 1.4 Stale examples — HIT (medium)
`systematic-debugging/references/` ships 209 lines of eval scaffolding from another harness:
- `test-pressure-1/2/3.md`, `test-academic.md` — pressure-test roleplay scenarios ("You're the on-call engineer… $15,000/minute") referencing `skills/debugging/systematic-debugging`, a path that doesn't exist in this repo. Tuned for a different setup, never runnable here.
- `CREATION-LOG.md` (119 lines) — provenance artifact of the original author.

The four real references (root-cause-tracing, defense-in-depth, condition-based-waiting ×2) are fine. No old-model few-shots or stale version pins anywhere else — github-actions correctly teaches SHA pinning over mutable tags (L45–49).

**Fix:** delete the five stale files; keep the skill.

### 1.5 Contradictory rules — HIT ×2
1. **brainstorming: description vs body.** Description: *"Use ONLY when intent is genuinely unclear… NOT for well-specified changes — just do those."* Body L19: *"Every project goes through this process. A todo list, a single-function utility, a config change — all of them."* Opposite trigger semantics in the two places that matter most (description gates invocation; body governs execution). **Fix:** make L19 say the design gate applies to genuinely-open work only, per the description.
2. **web-search: forced install vs AGENTS.md.** Skill: *"Do not skip this step or fall back to other tools"* for `curl -fsSL https://cli.tavily.com/install.sh | bash`. AGENTS.md: *"Ask before: install packages."* The skill also forces pipe-to-shell (see §3). **Fix:** ask first when `tvly` is missing.

Not contradictions, verified: ship.md's "this invocation approves commit+push, do not re-ask" is a documented carve-out of AGENTS.md's ask-before-commit (the prompt *is* the approval). systematic-debugging's "even simple issues" vs ponytail's "simplest thing that works" is resolved by their disjoint trigger scopes.

## 3. Security
- `tavily/config.json` holds a plaintext OAuth access_token. **Mitigated:** directory is 0700 and the file is gitignored (`.gitignore:32`). No action.
- **web-search pipe-to-shell install (medium):** unpinned `curl | bash` with an instruction to never skip or fall back — combines supply-chain exposure with a forced action. Pin the install (versioned URL or checksum) and gate it behind asking.
- browser-tools: vendored `node_modules` from a third party (Mario Zechner) — lockfile present, acceptable provenance. Minor: declares `puppeteer ^24` *and* `puppeteer-core ^23` — version split doubles the dep surface; align on one major.
- extensions — **PASS**: permission-gate/handoff contain no secrets; safe-bash deny-wraps the bash tool (pattern block, no allowlist bypass).
- github-actions skill — **PASS** (exemplary SHA-pinning guidance).
